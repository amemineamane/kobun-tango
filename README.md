# 古文単語帳

大学入試向け古文単語 **330 語**に、**関連語**・**作品タグ**、そして
**教科書の定番教材 20 編＋共通テスト・センター試験の出典 7 編
（原文＋現代語訳＋全文の品詞分解）** を足した単語帳アプリ。
文章ごとに「その文章に出てくる単語だけ」で学習・クイズができる。
ビルド不要・依存ライブラリなしの静的アプリで、`index.html` を開くだけで動く。

---

## 起動のしかた

### いちばん簡単（推奨）

`D:\kobun_app\index.html` を **ダブルクリック**。それだけ。

`file://` で開いてもすべての機能が動く（データを JSON ではなく `.js` として読み込んでいるため）。
学習履歴もそのブラウザの localStorage に保存される。

### ローカルサーバーで開く

URL を短くしたい／スマホから同じ LAN で見たいときは、PowerShell で:

```powershell
cd D:\kobun_app
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

`http://localhost:5520/` が開く。ポートを変えるなら `-Port 5600`。
停止は `Ctrl+C`。Python が入っていない場合は自動的に `file://` で開き直す。

> Windows の cp932 問題（日本語入り `.bat` が文字化けする）を避けるため、`.bat` は用意していません。

## 使い方

開くと **ホーム**（`#/`）が出る。ここから 4 つの画面（単語・教科書・学習・クイズ）へ行く。
メニューはヘッダ右（スマホでは画面下のタブ）。
「作品から入る」と「文章から入る」の二重の入口をやめ、**「教科書」1 つ**にまとめてある
（教科書 → 作品名で作品ページ、文章名で本文ページ、という一本道）。
**ホームへはヘッダ左のタイトル**、**使い方ページへはヘッダ右の「使い方」**から戻れる。

### ホーム（`#/`）

- アプリの説明と、大きな 3 つの導線「単語を学習する」「教科書の文章を読む」「クイズ」。
- **学習の状態**：330 語の「覚えた／苦手／未学習」と進捗バー。
  最後に学習したデッキ・最後に読んだ文章があれば **「続きから」** が出る。
  記録がまだ無いときは、代わりに「まず S 最重要の 114 語から」の案内になる。
- **今日のおすすめ**：苦手が溜まっていれば「苦手 N 語を復習」を先頭に固定で出す。
  そのうえで、未学習が残っている**文章・作品・重要度/品詞**（無ければ五十音行）から
  日付をシードにした擬似乱数で毎日 2〜3 件を選んで添える（同じ日は同じおすすめ）。
- **入口カード**：重要度（S/A/B）・品詞・学年・教科書の文章・**入試の出典作品**
  （`#/textbook?grade=入試`）へのショートカット
  （「作品から選ぶ」は「教科書」に統合したので置いていない）。
  リンク先は単語一覧の絞り込み URL（`#/words?level=S` など）なので、そのまま学習・クイズに進める。

### 使い方（`#/help`）

できること／重要度の意味／検索のコツ／学習の進め方／カードとクイズの操作／文章ページの見方／
**学習履歴の扱い（このブラウザにだけ保存され、サーバーには送らない）とリセット**／
データの出どころ／動作環境を 1 枚にまとめてある。
`#/help?to=history` のように節を指定して開ける（ホーム末尾や使い方目次のリンクがこれを使う）。

### 利用規約・プライバシーポリシー（`#/terms`）

利用条件と、個人情報・アクセス解析の扱い。`#/terms?to=privacy` で後半（プライバシーポリシー）に飛べる。
メニューには入れていない。フッタの制作者行・ホーム末尾・使い方ページ（制作／履歴リセット／解析の表記）からたどる。

### 重要度 S・A・B

単語には入試での問われやすさで 3 段階の重要度が付いていて、バッジと行頭の色帯で示す。
記号だけでは伝わらないので、バッジには必ずラベルを併記し、一覧・ホーム・使い方に凡例を出している。

| バッジ | 意味 | 語数 |
|---|---|---|
| **S 最重要**（赤） | 共通テストで必ず問われる中核語 | 114 |
| **A 頻出**（橙） | 合否を分ける頻出語 | 111 |
| **B 応用**（青緑） | 難関大で差がつく語 | 105 |
| **P 文章の語**（灰） | 教科書の脚注に出る語。330 語には無く、その文章の中だけで覚える | — |

### 単語

- **検索**：かな（`つれづれ` / `つれつれ` どちらでも可）、ローマ字（`tamafu`、`wokashi`）、
  漢字（`浅`）、意味（`早朝`）のいずれでも引ける。
- **フィルタ**：重要度（S/A/B）・品詞・五十音行・作品・学習状態。
- **並び順**：五十音順／重要度順／品詞順。
- 絞った条件のまま「この N 語で学習」「この条件でクイズ」に進める。
- 絞り込み条件は URL に入るので、**ブックマークできる**
  （例：`#/words?level=S&pos=敬語`）。
- **「文章」フィルタ**を選ぶと、330 語ではなく「その教材に出てくる語だけ」が対象になる
  （教科書の脚注に出るような、330 語に無い語も混ざる）。

### 単語詳細（`#/word/39` のように直リンク可）

- 語義、学習状態（未学習／苦手／覚えた）の切り替え。
- **関連語カード**：類義・対義・派生・同音注意・混同注意・段階。タップで相手の語へ。
- **この語が出てくる文章**：教科書教材のうち、その語が実際に出てくる段落を
  **原文のまま**並べる。その語は色を変えて示し、原文のどの語も
  **タップすると品詞分解がポップアップ**する。段落名から文章ページへ飛べる。
- 五十音順で前後の語へ移動できる。

### 教科書（`#/textbook`）

古典の本文の入口。**作品ごとに文章（教材）がまとまって**並ぶ。
一覧は **2 つのセクション**に分かれている。

1. **教科書の定番教材** … `data/works.js` の順（教科書での定番順）
2. **共通テスト・センター試験の出典作品** … **出題年の新しい順**

- 作品の見出し行には、作者・時代・ジャンルと **文章数・収録語数** が出る。
  **作品名をタップすると作品ページ**（`#/work/makura`）へ。
- 各文章のカードには **段落数・語数・学習進捗（覚えた/総数）** が出る。
  **文章名をタップすると本文ページ**（`#/passage/makura-haru`）へ。
- **学年の目安**（中1〜中3・高校・入試）でしぼれる（`#/textbook?grade=中2`）。
  **`?grade=入試` を選ぶと出典作品のセクションだけ**が出る。
- 文章がまだ無い作品も「文章はまだありません／収録語 N 語」として出る。

出典作品のセクションには、各作品に **`2025 共通テスト` のような出題バッジ**が付く
（複数年の出題は全部出る）。本文を収めた作品は文章カードで、本文が未収録の作品は
**「本文は未収録（作品の解説のみ）」の畳んだ 1 行**で並ぶ。
共通テストの古文は教科書に載らない作品から出るので、**初見の文章を単語と文法だけで読む練習**
として使える。載せているのは著作権保護期間の満了した原文と、このアプリのために書き下ろした
現代語訳だけで、**試験の設問・注・リード文は載せていない**
（出典の裏取りは [`docs/exam-sources.md`](docs/exam-sources.md)）。

> 旧 URL の `#/works`（作品一覧）と `#/passages`（文章一覧）は `#/textbook` に転送される。
> `#/work/<id>` `#/passage/<id>` はそのまま使える。

### 作品ページ（`#/work/makura` のように直リンク可）

作品の書誌と紹介、その作品の文章（教材）と収録語。収録語には由来のバッジが付く。
入試の出典作品では、タイトルのすぐ下に出題バッジが出て、
**「入試での出題」**（年・試験・本試験/第1日程・出題箇所）がカードでまとまる。
本文が未収録の作品でも、この出題情報と作品の解説でページが成り立つようにしてある。

- `文章` … その作品の教材本文に出てくる語（`vocab` または品詞分解の重要語）
- `タグ` … 本文に出てこないが「この作品で重要」と手で紐づけた語

「この作品の単語で学習／クイズ」からそのまま演習に進める。

### 文章（`#/passage/makura-haru` のように直リンク可）

教材を**原文と現代語訳**で読む画面。
- 原文と訳は段落ごとに対応表示。**「訳を隠す」「横に並べる」** で読み方を切り替えられる
  （設定はブラウザに記憶される）。
- **原文のどの語をタップしても品詞分解が出る**（品詞・活用の種類・活用形・
  その文脈での意味）。重要 330 語なら、そのまま単語詳細へ飛べる。
  青い実線 = 330 語、橙の点線 = その文章の脚注語、下線なしの語もタップできる。
- 段落ごとの **「品詞分解を表で見る」** で、全語を一覧表でも確認できる。
- 下部に「この文章の単語」一覧。**「この文章の単語で学習」「この文章の単語でクイズ」**
  から、その文章の語だけで演習できる。

入試の出典から採った文章には、タイトルのそばに **出題バッジ**（`2025 共通テスト`）と
「〜年度〜の出典作品です」の 1 行が出る。同じ作品の別の場面を収めたものもあるので、
その文章が出題箇所そのものかどうかは本文の下の注記に書いてある。

収録している教材は 27 編。教科書の定番 20 編（竹取物語・伊勢物語・枕草子・徒然草・
土佐日記・更級日記・平家物語・方丈記・源氏物語・宇治拾遺物語・おくのほそ道・古今和歌集）と、
入試の出典 7 編（今昔物語集・増鏡・とはずがたり・源氏物語）。

### 学習（フラッシュカード）

フィルタで作ったデッキを 1 枚ずつ。表＝見出し語、めくると語義と用例（その語が出てくる段落）。

| 操作 | 動作 |
|---|---|
| `Space` / `Enter`／カードをタップ | めくる |
| `→`／「覚えた」ボタン／**右へスワイプ** | 覚えた |
| `←`／「まだ」ボタン／**左へスワイプ** | まだ（苦手） |

**めくる前は「覚えた／まだ」を選べない**（ボタンは薄く、`←` `→` とスワイプも効かない）。
答えを見ずに記録が付いて進捗が実態とずれるのを防ぐため。押すと「先にめくって答えを確認」と出る。

スワイプは裏面だけ。右か左に 80px 以上払うとカードが飛んで次の語に進み、
途中で止めて戻せば記録は付かない。指でもマウスのドラッグでも同じように動く
（縦スクロールは妨げない）。

一周したら「まだの語だけで復習」ができる。

### クイズ（4択）

誤答は**同じ品詞の別語**から選ばれるので、意味の近い選択肢が並んで難度が上がる。
文章を指定したとき（`#/quiz?passage=...`）は、誤答も**同じ文章の他の語**から選ばれる。

- 出題形式：語 → 意味／意味 → 語
- 問題数：5 / 10 / 20 / 30
- `1`〜`4` の数字キーで回答できる
- 正解した語は「覚えた」、間違えた語は「苦手」として自動保存
- 終了後に「間違えた語だけ出題」で復習できる

## 共有する

各ページに共有ボタンがある。渡すのは **公開ページの絶対 URL**（手元で `file://` や
`localhost` で開いていても、`data/site.js` の `url` を土台に組み立てる）。

| 画面 | 共有される文面 |
|---|---|
| クイズの結果 | 「古文単語クイズ 10 問中 8 問正解（正答率 80%）！【重要度 S 最重要】」＋**同じ条件で始められる URL** |
| 単語（`#/word/:id`） | 「『をかし』＝趣がある・風情がある｜古文単語帳」 |
| 文章（`#/passage/:id`） | 「枕草子『春はあけぼの』を原文と現代語訳で読む｜古文単語帳」 |
| 作品（`#/work/:id`） | 「『徒然草』の単語と文章｜古文単語帳」 |
| 学習の完走画面 | 「古文単語帳のフラッシュカードで【…】○ 語を 1 周しました！」 |
| ホーム・使い方 | 「古文単語帳｜入試向けの古文単語 330 語と…」 |

- スマホ（`navigator.share` が使える指で触る画面）では「共有」1 つ＋「リンクをコピー」。

- 「リンクをコピー」は 2 秒だけ「コピーしました」と出る。

## アプリとして使う（ホーム画面に追加）

`manifest.webmanifest` と `sw.js`（Service Worker）を置いてあるので、
公開ページからホーム画面・デスクトップに追加できる。

- **Android（Chrome）** … ホームか使い方ページの「ホーム画面に追加」ボタン、
  または ⋮ メニューの「アプリをインストール」。
- **iPhone・iPad（Safari）** … 共有ボタン →「ホーム画面に追加」
  （iOS には `beforeinstallprompt` が無いのでアプリ側のボタンは出ない）。
- **PC（Chrome / Edge）** … アドレスバー右端のインストールアイコン。

キャッシュの方針は **network-first**（ネットを先に見て、失敗したときだけキャッシュ）。
データを直したのに古い本文が出る、という事故を避けるため。
一度ひらいたページはオフラインでも読める。新しい版があるときは、勝手に入れ替えず
画面下に「新しいバージョンがあります — 再読み込み」のバーを出す。

`file://` で直接開いているときは Service Worker が登録できない仕様なので、
この機能だけ使えない（ほかは今までどおり動く）。

アイコンの元データは `assets/icon.svg`（maskable は余白を広く取った `assets/icon-maskable.svg`）。
PNG は Chrome の headless スクリーンショットで書き出す。

```powershell
# 例：512×512 を書き出す
& "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless=new --disable-gpu `
  --window-size=512,512 --screenshot=assets\icon-512.png assets\icon.svg
```

## アナリティクスの設定

アクセス解析の設定は **`data/site.js` の `analytics`** 1 か所にある。
**空文字にしておくと、そのサービスは読み込まれない**（両方空なら外部通信はゼロ）。

```js
analytics: {
  ga4: 'G-XXXXXXXXXX',   // Google アナリティクス 4 の測定 ID。空なら無効
  cloudflare: ''         // Cloudflare Web Analytics のトークン。空なら無効
}
```

- 計測するのは **http / https で開いたとき**だけ。`file://` では何もしない。
- `localhost` ／ `127.0.0.1` ／ `*.local` は**デバッグモード**。外部スクリプトを読み込まず、
  送るはずだった内容を開発者ツールのコンソールに `console.debug` で出すだけ（送信はしない）。
- 実装は `js/analytics.js`。画面側は `KOBUN.analytics.pageview()` と
  `KOBUN.analytics.event()` を呼ぶだけで、無効なときは何もしない。

**測定 ID / トークンの取り方**

| サービス | 手順 |
|---|---|
| Google アナリティクス 4 | <https://analytics.google.com/> でプロパティを作る → 「データストリーム」でウェブのストリーム（URL は公開ページ）を追加 → 表示される **測定 ID `G-XXXXXXXXXX`** を `ga4` に貼る。 |
| Cloudflare Web Analytics | <https://dash.cloudflare.com/> → Analytics & Logs → Web Analytics → 「Add a site」で公開ページのホスト名を登録 → 出てくる JS スニペットの **`token` の値**（32 桁の英数字）だけを `cloudflare` に貼る（スニペット自体は貼らない）。 |

貼り替えたら `node tools\bump-version.mjs` を実行してから公開する。

**何を送るか**

| イベント | パラメータ | いつ |
|---|---|---|
| `page_view` | `page_path` `page_title` `page_location` | 画面を描き終えたとき（検索語 `?q=` はパスから除く） |
| `quiz_complete` | `deck` `deck_id` `count` `correct` `score_pct` | クイズを最後まで解いたとき |
| `study_complete` | `deck` `deck_id` `count` `known` `weak` | フラッシュカードを 1 周したとき |
| `share` | `method`（native/x/line/copy）`content_type` `item_id` | 共有ボタンを押したとき |
| `search` | `hit_count` `has_query` | 単語検索（**検索語そのものは送らない**） |

| `passage_view` | `passage_id` `work_id` | 文章を開いたとき |
| `token_tap` | `passage_id` | 原文の語をタップしたとき |
| `install_prompt` / `app_installed` | `outcome` | ホーム画面に追加したとき |
| `history_reset` | — | 学習履歴をリセットしたとき |

**送らないもの**：検索語、学習履歴の中身（どの語を覚えたか）、語ごとの「覚えた／まだ」。

詳細は [`#/terms?to=privacy`](#利用規約プライバシーポリシー) に置いている
（`ga4` を空にすると、そちらも「現在アクセス解析は使用していません」に切り替わる）。

## 学習履歴について

- ブラウザの **localStorage** に保存される（キーは `kobun.v1.*`）。
- 保存キーは単語の **`id`**。`ながむ`〔眺む〕/〔詠む〕のように同じ仮名の別語があるため、
  仮名ではなく id で管理している。
- 教材の脚注語（330 語に無い語）だけは id を持たないので、
  `p:<文章id>:<番号>` という別のキーで記録している。
  330 語の進捗表示（「全 330 語｜覚えた …」）には混ざらない。
- 最後に学習したデッキ・最後に開いた文章も覚えていて、ホームの「続きから」に出る
  （`kobun.v1.recent`）。
- **ブラウザ・端末ごとに別**。同期はしない。**学習履歴の中身（どの語を覚えたか）は
  サーバーに送らない**（アクセス解析で送るのは「クイズを完走した」などの利用状況だけ。
  上の「アナリティクスの設定」参照）。
- 履歴を消すには **使い方ページ（`#/help?to=history`）の「学習履歴をリセットする」**。
  2 段階のボタンになっていて、確認してから消える（進捗・クイズ履歴・「続きから」が対象。
  訳の表示などの画面設定は残る）。ブラウザのサイトデータを削除しても消える。
- プライベートウィンドウ等で localStorage が使えないときは、
  画面上部に注意が出て、その場限りのメモリ保存に切り替わる。
- 取り扱いの正式な説明は `#/terms?to=privacy`（利用規約・プライバシーポリシー）にある。

## データを足す

`data/` の各ファイルの先頭に、日本語で「役割」と「追加のしかた」を書いてある。
詳しい手順は **[DESIGN.md](DESIGN.md) の「5. 拡張ポイント」** を参照。

足したあとは、**この順番で**コマンドを流す（どれもデータから作り直すだけなので、
途中まで実行しても壊れない。エラーが 0 になってから commit すること）:

```powershell
cd D:\kobun_app
node tools\sync-tokens.mjs    # 品詞分解のファイルを足した／消したときだけ
node tools\build-seo.mjs      # 検索エンジン向けの静的ページ（w/ p/ k/）と sitemap.xml を作り直す
node tools\validate.mjs       # データ整合性チェック（最後に validate-tokens.mjs も呼ぶ）
node tools\bump-version.mjs   # ?v=... と sw.js の CACHE_VERSION と生成ページの版を揃える
# ここまでエラー 0 なら commit → push
```

`build-seo` を忘れると、検索結果に出るページだけ古いデータのままになる
（アプリ本体は `data/*.js` を直接読むので正しく動いてしまい、気づきにくい）。

チェックする内容:

- `words` の id 重複、必須フィールド、`meanings` と `meaningCount` の整合
- `relations` の `from` / `to` が実在する単語か
- `workWords` の `workId` / `wordId` が実在するか、組み合わせの重複
- `passages` の id 重複、`workId` / `vocab[].wordId` が実在するか
- **`vocab[].surface` が本文（`paragraphs[].text`）に実際に出てくるか**
  （出てこないとハイライトされないので、原文との綴り違いをここで捕まえる）
- `meaningIndex` がその語の `meanings` の範囲内か
- `wordId` の無い `vocab` に `meaning` があるか／同じ `wordId` を 1 文章に 2 回書いていないか

続けて `tools/validate-tokens.mjs` が呼ばれ、品詞分解（`data/tokens/*.js`）も検査する:

- `passageId` が実在するか、段落数が `paragraphs` と合っているか
- **段落内の `s`（表層形）を連結したものが原文と一字一句一致するか**（食い違った位置を表示）
- 品詞・活用の種類・活用形が統一ラベル表の値か、`w` の重要語が実在するか
- 重要語のハイライトがトークンを割っていないか、まだ品詞分解が無い文章はどれか

品詞分解だけを見たいときは `node tools\validate-tokens.mjs` を直接実行する。

エラーが 0 になるまで直してから使うこと。

## 品詞分解を足す

教科書教材の原文には、語ごとの品詞分解を付けられる。付けると
**文章ページで原文のどの語をタップしても品詞・活用・語義が出る**ようになり、
段落ごとに「品詞分解を表で見る」も開ける。単語詳細の「この語が出てくる文章」にも
その段落が原文つきで並ぶ。まだ付けていない教材は、従来どおり重要語だけがタップできる。

1. **[docs/tokens-guide.md](docs/tokens-guide.md)** を読む（キーの意味・品詞ラベル表・
   活用の書き方・「なり」「ぬ」「に」など定番論点の扱いを決めてある）。
2. `data/tokens/<文章id>.js` を作る（`<文章id>` は `data/passages.js` の `id`）。
3. `node tools\validate-tokens.mjs` でエラー 0 にする。
4. `node tools\sync-tokens.mjs` を実行する。`index.html` の `<script>` と
   `sw.js` の `PRECACHE` が `data/tokens/` の実際の中身から作り直される
   （手で書くと、存在しないファイルを指して 404 になりやすい）。
5. `node tools\build-seo.mjs` を実行する。品詞分解が文章ページ（`p/<文章id>.html`）の
   一覧表と、単語ページの用例に反映される。

## 検索エンジン向けの静的ページ（SEO）

アプリはハッシュルーティング（`#/word/39`）なので、検索エンジンからは
**`index.html` 1 枚のサイト**にしか見えない。そこで `data/*.js` から
**実 HTML を機械的に生成**し、単語・文章・作品を 1 ページずつ検索結果に出せるようにしてある。
設計の考え方は [DESIGN.md「4-e. SEO」](DESIGN.md) を参照。

```powershell
cd D:\kobun_app
node tools\build-seo.mjs
```

| 生成物 | 中身 |
|---|---|
| `w/<単語id>.html`（330 枚） | 見出し語・漢字・品詞・重要度・語義一覧・関連語・その語が出てくる段落（原文と現代語訳つき）・登場作品・五十音の前後 |
| `w/index.html` | 330 語を重要度別と五十音別に並べた一覧 |
| `p/<文章id>.html` | 作品・教材名・段落ごとの原文と現代語訳・**全語の品詞分解の表**（表層形／基本形／品詞／活用／語義）・その文章の重要語 |
| `p/index.html` | 教材の一覧（作品ごと） |
| `k/<作品id>.html` | 作者・時代・ジャンル・概要・収録教材・収録語 |
| `k/index.html` | 作品の一覧 |
| `sitemap.xml` / `robots.txt` | 上のすべての URL（`lastmod` は生成日）と `Sitemap:` 行 |

- 生成ページは**アプリと同じ `css/style.css`** を読み、簡易ヘッダと「アプリで開く」
  （`../#/word/39`）を置くだけ。**JS でのリダイレクトはしない**
  （クローラにも読者にも本文をそのまま読ませる。PWA としてスタンドアロン起動しているときだけ
  アプリ側の画面に置き換える小さなスクリプトが入っている）。
- アプリ名・公開 URL・制作者は `data/site.js` から取るので、名前や URL を変えたら
  `build-seo` を流し直すだけでよい。
- **生成物は手で編集しない**（次の実行で消える）。`w/ p/ k/` の `*.html` は毎回作り直される。
- 生成ページは `sw.js` の precache には**入れない**（枚数が多い。
  network-first の通常の fetch で足りる）。
- 共有ボタンの URL は**ハッシュのまま**（`#/word/39`）。履歴・PWA との整合を優先し、
  「正式な URL はこちら」は各画面の `<link rel="canonical">` で伝えている
  （`js/router.js` がハッシュ遷移のたびに `w/39.html` などへ書き換える）。

### Search Console に登録する

1. <https://search.google.com/search-console/> でプロパティ（URL プレフィックス）
   `https://amemineamane.github.io/kobun-tango/` を追加する。
2. 所有権の確認方法として「HTML タグ」を選び、表示される
   `<meta name="google-site-verification" content="○○○">` の **content の値**をコピーする。
3. `index.html` の `<head>` にコメントで用意してある枠の
   **コメント記号（`<!--` と `-->`）を外して**、content に貼る。

   ```html
   <meta name="google-site-verification" content="ここに貼る">
   ```
4. `node tools\bump-version.mjs` を実行してから commit・push する。
5. GitHub Pages に反映されたら、Search Console で「確認」を押す。
6. 確認できたら左メニューの **「サイトマップ」** に
   `https://amemineamane.github.io/kobun-tango/sitemap.xml`
   を送信する（プロパティのルートが `/kobun-tango/` なので `sitemap.xml` と入力すればよい）。

> `robots.txt` もリポジトリの直下に生成しているが、GitHub Pages の
> プロジェクトページでは実際に読まれるのはドメイン直下
> （`https://amemineamane.github.io/robots.txt`）のほうなので、
> クロールの入口はサイトマップの送信で確保している。

## 公開前のキャッシュ対策

GitHub Pages は `Cache-Control: max-age=600` を返すため、公開直後は
「新しい `index.html`」と「古いままの `js`/`css`」がキャッシュに混在することがある
（例: ルーターだけ新しくて画面が「ページが見つかりません」になる）。
これを避けるため、`index.html` の `<link>`/`<script>` には `?v=YYYYMMDDx`
（日付＋連番アルファベット）を付けてある。**公開前に必ず**次を実行してから
commit・push すること。

```powershell
cd D:\kobun_app
node tools\bump-version.mjs
```

`index.html` 内の `?v=...` をすべて今日の日付＋連番に一括更新し、
**あわせて `sw.js` の `CACHE_VERSION` と、SEO 用の生成ページ（`w/ p/ k/` の `*.html`）の
`?v=...` も同じ値にする**（引数なし）。
Service Worker のキャッシュ名はこの版から作るので、版が変わると古いキャッシュが捨てられる。
タグの並びなど `index.html` の構造は変えないので、`file://` で直接開く用途にも影響しない。

## 注意

- `data/works.js` `relations.js` `workWords.js` `passages.js` `tokens/*.js` は
  プロトタイプ用に書き起こしたもの。**一次校閲済み**で、裏取りの記録は
  [docs/verification.md](docs/verification.md) にある（各ファイル冒頭の「サンプル・要校閲」は
  校閲前に書いた注記）。
- 教材の**原文は著作権の切れた古典本文**だが、底本によって異同がある
  （異同は `note` に「底本異同: …」として残してある）。
  長い教材は有名部分を抜き、省いた箇所は本文中に `（中略）` と書いてある。
  **現代語訳はこのアプリのために書き起こしたもの**で、教科書・市販訳の転載ではない。
- 解釈の分かれる品詞分解・語義には `note` に「要確認」と書いてあり、
  画面上では**橙色＋破線**で目立つようにしてある。
- 単語 330 語の内容は素材そのまま。素材の仕様書にも
  「公開アプリに載せる前に手元の辞書で最終確認を」とある。

## 動作環境

Chrome / Edge / Firefox / Safari の最近のバージョン。
データの読み込みに `fetch` も ES モジュールも使っていないので、`file://` でも制限なく動く
（Service Worker は http/https でしか登録できないため、`file://` では PWA 機能だけ使えない）。
スマホ幅にも対応（レスポンシブ）。OS のダークモード設定に自動で追従する。
