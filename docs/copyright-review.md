## 0. このレビューの読み方

- 各項目の判断は **問題なし／注意／要対処** の 3 段階。
  「要対処」はこのレビューの中で**すでに直したもの**だけを指す（直していないものは「注意」に落とす）。
- 判断の根拠は、実際に取得した各サイトの利用規約・ライセンス表示の**引用**で示す。
  引用できなかったものは「確認できず」と書く。**憶測で「たぶん大丈夫」とは書かない。**
- これは法的助言ではない。争いのある論点（とくに §1 の 校訂本文の著作物性）は
  「争いがある」と明記し、安全側の対処を採った。

## 1. 原文（`data/passages.js` 44 編）と取得元サイトの利用条件

### 1-0. 前提

古典本文そのものは**著作権の保護期間が満了**している。問題になるのは、
web 上で公開されている **翻刻**（写本・版本の字を起こしたもの）と
**校訂本文**（諸本を比べ、句読点・表記を整えたもの）に、
取得元サイトがどんな条件を付けているか、である。

**日本法における校訂本文の著作物性には争いがある。**
やたナビTEXT 自身は「翻刻部分は著作権が存在しません」としつつ
「校訂本文部分は CC BY-SA」としており、翻刻と校訂を区別している。
本レビューは**安全側**、すなわち「サイトが付けた条件には従う」立場で対処した。

### 1-3. 翻刻と校訂本文の法的な位置づけ（調べた範囲）

**判例は見つからなかった。** 裁判所の裁判例検索・知的財産事件裁判例検索、
デジタルアーカイブ学会 法制度部会の論考（https://www.jstage.jst.go.jp/article/jsda/7/4/7_173/_pdf/-char/ja。
本文に「翻刻」「校訂」「古典籍」「古文書」の語が 1 度も出てこない）を当たったが、
**古典籍の翻刻・校訂本文の著作物性を判断した日本の裁判例は確認できなかった**。
判例名を挙げて論じることはできない。

代わりに、根拠として引ける公的・準公的な記述は次のとおり。

- **文化庁『著作権テキスト 令和 7 年度版』** p.5（著作物性の要件）
  https://www.bunka.go.jp/seisaku/chosakuken/seidokaisetsu/pdf/94283401_01.pdf
  > 「（b）「創作的」に　他人の作品の「模倣品」など（創作が加わっていないもの）が著作物から除かれます。また、「ありふれたもの」（誰が表現しても同じようなものになるもの）も創作性があるとはいえません。」

  文化庁の資料に「翻刻」を名指しで論じた記述は見つからなかった。

- **日本書籍出版協会「日本の出版界と出版物の著作権について」**（文化庁 著作権実務講習会 配付資料）p.4
  https://www.bunka.go.jp/seisaku/chosakuken/seidokaisetsu/pdf/94053901_09.pdf
  > 「b. 古典の校閲、注釈
  > ・古典作品自体は著作権保護期間が経過している。
  > ・校閲をしたり、注釈をつけたりする場合、そこに著作権が発生する場合がある。
  > ⇒ たとえば、源氏物語の原文を複製することは自由。しかし、既存の古典文学全集の版面をそのまま複製すると、著作権処理を必要とする場合がありうる。」

  出版社側の団体の資料でも「発生する**場合がある**」「必要とする**場合がありうる**」という
  留保付きの言い方で、校訂に必ず著作権が生じるとは述べていない。

- **やたナビTEXT の解説**（翻刻と校訂の区別）
  https://yatanavi.org/rhizome/翻刻
  > 「著作権的には純粋な翻刻には発生しないと考えられるが、」……「校訂本文には著作権が発生する可能性があるので注意が必要である。」

  同サイトは実際に「翻刻部分はパブリックドメインで、校訂本文部分は CC BY-SA 4.0」として
  2 つを分けて公開している（https://yatanavi.livedoor.blog/archives/53368769.html）。

- **国立国会図書館の複製・利用案内** https://www.ndl.go.jp/jp/use/reproduction/index.html
  「インターネット公開（保護期間満了）」の資料について
  > 「著作権保護期間が満了していますので、自由にご利用いただけます。」

**この整理を踏まえた本レビューの立場**:
純粋な翻刻は著作物性が無いと考えるのが有力（ただし判例で決着していない）、
校訂本文は生じうるので**サイトが付けた条件に従う**、注釈・現代語訳は明らかに著作物。

#### A・B・C ── 帰属表示を実装した（実施済み）

`js/view-terms.js` の第 3 条のあとに **「第 3 条の 2（本文の出典とライセンス）」** を新設し、
画面（`#/terms`）に次を出すようにした。

1. **やたナビTEXT の校訂本文** … 校訂者 **中川聡（Satoshi Nakagawa）**／`https://yatanavi.org/text/`／
   **CC BY-SA 4.0** へのリンク。該当教材（伊勢物語 第一段・第四段／徒然草 第十一段・第八十九段／
   十訓抄 三の一／とはずがたり 巻一）を明記。同サイトの今昔物語集は**翻刻＝著作権なし**である旨も書いた。
2. **Wikisource『源氏物語（渋谷栄一校訂）』** … 校訂者 **渋谷栄一**／ページ URL／**CC BY-SA 3.0** へのリンク。
3. **Wikisource のその他の翻刻** … 作品と底本（國民文庫・國文大觀・有朋堂文庫・校註増鏡・群書類従）を列挙し、
   `ja.wikisource.org` と **CC BY-SA 4.0** へのリンク。
4. 本文に加えた改変（表記・句読点・段落の整え、抜粋、旧字体の現代化）を明記し、
   passage ごとの取得元は `docs/passage-notes.md`、条件の確認結果は `docs/copyright-review.md` を見よ、と書いた。

あわせて **第 3 条に ShareAlike の逃げ道を作った**。従来の第 3 条は
「無断での転載・再配布…はご遠慮ください」と一律に書いていたが、
CC BY-SA の本文についてこれを主張すると継承条件に反する。そこで

> 「ただし次条の『本文の出典とライセンス』に挙げた原文については、もとのライセンス（CC BY-SA）が優先します。それらの原文は、もとの著作権者名とページの URL を明記し、同じライセンスで公開する限り、この規約の制限を受けずに転載・再配布していただけます。」

という但し書きを足した。

**なぜ画面に出したのか** ── 作業 2 で passage の `note` から URL・底本名を外したので、
帰属表示の置き場所が必要だった。CC BY-SA は「媒体に応じた合理的な方法」での帰属を求めるので、
全 passage の画面に URL を並べる代わりに、**規約ページに 1 か所まとめる**形にした。

#### D ── JTI を本文の取得元から外した（実施済み）

`makura-kisaragi`（枕草子 第百六段）の記録は
「この段を載せる公開テキスト **14 種**（教材サイト・個人訳注・University of Virginia Japanese Text Initiative の
枕草子全文）を突き合わせ、三巻本系の教科書本文に揃えて確定した」となっていた。

- JTI の利用条件は "may not be downloaded or copied" で、**複製を明示的に禁じている**。
- ただし本アプリの本文は、14 種を突き合わせて**共通して現れる三巻本系の教科書本文**に揃えたもので、
  JTI 固有の校訂を写したものではない（JTI は 14 分の 1 の照合先）。
- それでも「取得元」として JTI を挙げるのは実態と条件の両方から適切でないので、
  **JTI を照合先の一覧から外し、残る 13 種による確定として記録を改めた**
  （`docs/passage-notes.md` の該当項に追記）。
- さらに、**ライセンスの明らかな PD の翻刻を照合先に足した**。
  Wikisource **『枕草紙 (國文大觀)』** https://ja.wikisource.org/wiki/枕草紙_(國文大觀)
  （底本『國文大觀 第九編日記草子部』板倉屋書房 1903。ページのライセンステンプレートは
  `{{PD-old-auto-1923|deathyear=1935}}`）にこの段があり、冒頭は
  > 「二月つごもり、風いたく吹きて空いみじくくろきに雪すこしうちちりたる程、黑戶にとのもづかさきて、」

  **注意**: 國文大觀本は「**公任の君、宰相中將殿の**」で、本アプリの三巻本系教科書本文
  「これ、公任の宰相殿の」とは**伝本の系統が違う**（春曙抄＝能因本系の流れ）。
  したがって PD の**代替本文**にはならず、**独立した照合先**として使える、という位置づけである。
  なお Wikisource の `枕草子 (Wikisource)/第百六段` は**存在しない**（目次では赤リンク）。

#### E ── koten.net の扱い（注意・付け替えは未了）

`heike-ogi` `heike-atsumori` `heike-kiso` の記録は
「日本古典文学摘集『平家物語』…の校訂原文 … と**機械照合**し、
教科書で一般的な覚一本系の本文に句読点・送り仮名を整えて収めた」。
`ujishui-chigo` `hojoki-yukukawa` `hosomichi-tabidachi` でも照合に使っている（`docs/verification.md` §1）。

事実関係を記録から確認すると:

- 摘集との**語句の相違は「表記だけ」と句読点だけ**だった

## 6. 画像・アイコン・フォント ── **問題なし**

### 6-1. `assets/` の画像はすべて自作

`assets/*.svg` 3 点（`favicon.svg` `icon.svg` `icon-maskable.svg` `ogp.svg`）は
`<rect>` と `<text>` だけで書かれた手書きの SVG で、外部から取り込んだパスは無い。
`*.png` 5 点は、その SVG を headless Chrome でスクリーンショットして書き出したもの
（生成コマンドは `icon.svg`・`ogp.svg` のコメントと `README.md` に書いてある）。

### 6-2. 外部フォントは不使用

- `@font-face` は 0 件。`fonts.googleapis.com` / `fonts.gstatic.com` への参照も 0 件。
- 書体は CSS 変数 `--font-ja` / `--font-serif` の**フォントスタック**（システムフォント名の羅列）だけ。
  `system-ui, -apple-system, "Segoe UI", "Yu Gothic UI", …` ／ `"Yu Mincho", "Hiragino Mincho ProN", …`
- PNG／OGP 画像は、そのシステムフォントで描いた文字を**ラスタライズした画像**である。

Microsoft の Font redistribution FAQ（https://learn.microsoft.com/en-us/typography/fonts/font-faq）が
この 2 点を明示的に許している。

> "Can I make graphic files using the fonts, say a screengrab, advertisement, meme or poster and share, sell or redistribute those graphic files?" — "We view creating graphic files as being essentially the same as printing from an output device."

> "Web content publishers are free to specify Windows supplied fonts in their font stacks. In fact, as a web page creator you don't even need to be a Windows licensee to include a Windows font name in a CSS font stack, as the "use" of the font occurs on the Windows device, not on your web server."

禁じられているのは**フォントファイル自体の再配布**（web font としての self-hosting、WOFF への変換）で、
本アプリはどちらも行っていない。

> "You do not have rights to: copy fonts from a Windows installation to a web server, a process known as web font "self-hosting"."

### 6-3. ナビと共有ボタンの SVG アイコンは既存アイコンセットの複製ではない

`index.html` のナビ 5 個と `js/components.js` の `ICON_PATHS` 8 個は、いずれも
`viewBox="0 0 24 24"` ・ `stroke="currentColor"` ・ `stroke-width="1.8"` で手書きした線画。
24×24・線画・`currentColor` という**約束事**は Feather / Lucide などと同じだが、
これは SVG アイコンの一般的な作法であって、パスデータは一致しない
（そもそも「見開きの本」「しおりを挟んだ本」「活用表」のような、
既存セットに同じ意味の図案が無いものが多い）。
コメントに「単語タブ（見開きの本）と形で区別する」のような作図の意図が残っている。

## 10. JSON-LD・OGP・規約ページ ── **問題なし**

- **JSON-LD**（`index.html` の `@graph`、および `tools/build-seo.mjs` が各ページに埋めるもの）
  `WebSite` / `SoftwareApplication` / `DefinedTerm` / `Article` / `Book` の 5 型。
  `author` は制作者本人（雨峰あまね／`https://x.com/AmemineAmane`）だけで、
  第三者の名称・ロゴ・引用は入っていない。`schema.org` の語彙そのものは
  https://schema.org/ が公開する仕様で、利用に条件は付かない。
- **OGP / Twitter Card**
  `og:image` は自作の `assets/ogp.png`。`twitter:site` / `twitter:creator` は
  制作者自身のアカウント（`@AmemineAmane`）。`twitter:*` は事実上の標準メタタグで、
  X のロゴや商標を使うものではない。
- **規約ページ（`#/terms`）**
  第三者の名称は「Google LLC」「Google アナリティクス 4」「Cloudflare Web Analytics」だけで、
  いずれも**自社サービスを指す記述的な言及**（誰が何を提供しているかの説明）。
  第 2 条に「学校・塾・企業などの団体が運営するものではなく、教科書会社や出版社とも関係ありません。」
  という**非提携の明示**があり、出所の誤認を招く書き方はしていない。
  ロゴの掲示は無い。
